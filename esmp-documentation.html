01
Platform Overview

ESMP is a full-stack enterprise service management platform built on a Turborepo monorepo. It combines a NestJS REST API backend with a Next.js frontend, backed by PostgreSQL via Prisma ORM and Supabase for storage, with real-time capabilities via Socket.IO.

Monorepo structure: apps/api (NestJS) + apps/web (Next.js) managed by Turborepo with shared packages.
LayerTechnologyPurpose
Backend FrameworkNestJS (Node.js)REST API, WebSocket gateways, modular architecture
Frontend FrameworkNext.js 14 (App Router)SSR/CSR hybrid, role-based routing, client portal
DatabasePostgreSQL + Prisma ORMRelational data, migrations, type-safe queries
StorageSupabase StorageFile uploads, avatars, attachments
Real-timeSocket.IOChat, notifications, live updates
MonorepoTurborepoBuild orchestration, caching, task pipelines

  • ✓32 API ModulesFully modular NestJS architecture with dedicated controllers, services, and modules
  • ✓50+ DB ModelsComprehensive Prisma schema covering all platform entities and relationships
  • ✓Role-Based Access4 distinct roles (Admin/Manager/Employee/Client) with granular permission guards
  • ✓Real-Time WebSocketsSocket.IO gateways for chat, notifications, and live collaboration features

03
Authentication & Onboarding

ESMP uses a secure email-first authentication flow with OTP verification, JWT tokens, and a Gmail-only policy. New users go through a guided onboarding flow before accessing the platform.

Gmail-only policy: Only @gmail.com addresses are accepted for registration. This is enforced at both the API and UI layers.
  • ✓OTP Email Verification6-digit OTP sent via Nodemailer on registration and login; expires after 10 minutes
  • ✓JWT AuthenticationStateless JWT tokens with role claims; validated via Passport JWT strategy on all protected routes
  • ✓Gmail-Only PolicyRegistration restricted to @gmail.com addresses; enforced server-side with clear error messaging
  • ✓Role-Based RedirectAfter login, users are redirected to their role-specific dashboard (admin/manager/employee/client)
  • ✓Onboarding FlowNew users complete a profile setup wizard (name, avatar, department, designation) before accessing the platform
  • ✓Audit LoggingAll auth events (login, logout, OTP request, password change) are recorded in the audit log
  • ✓Password ChangeSecure password update flow with current password verification; available in Settings
  • ✓WebSocket AuthSocket.IO connections authenticated via WsJwtGuard — JWT validated on handshake
Auth EventActionLogged

Global Chat

Platform-wide messaging system allowing any user to connect with colleagues via direct messages or group chats. Chat requests are Gmail-based, and all messaging is real-time via Socket.IO WebSockets.

Global Chat is completely separate from Team Chat — different data models, different Socket.IO namespaces, and different UI sections.
  • ✓Chat RequestsInitiate a chat by searching a Gmail address; recipient must accept before messaging begins
  • ✓Direct Messages1-on-1 real-time messaging with read receipts, typing indicators, and message history
  • ✓Group ChatsCreate group conversations with multiple participants; group name and avatar customizable
  • ✓Real-Time WebSocketAll messages delivered instantly via Socket.IO; online/offline presence indicators
  • ✓Edit MessagesAuthors can edit sent messages; edited indicator shown with original timestamp preserved
  • ✓Delete MessagesAuthors can delete messages; "message deleted" placeholder shown to other participants
  • ✓View ProfilesClick any participant to view their profile card — name, avatar, role, department, designation
  • ✓Group ManagementAdd/remove members, rename group, leave group, delete group (creator only)

Team Chat

Each team has a dedicated, scoped chat room accessible only to team members. Team Chat is a completely separate system from Global Chat with its own features tailored for team collaboration.

Team Chat uses a separate Socket.IO gateway, separate database tables, and a separate UI section from Global Chat — they do not share any infrastructure.
  • ✓Team-Scoped RoomEach team has exactly one chat room; only team members can access it; auto-created with the team
  • ✓Message TypesSupport for text, file attachments, images, and system messages (member joined/left)
  • ✓Pin MessagesLeaders and reviewers can pin important messages; pinned messages shown in a dedicated panel
  • ✓Edit & DeleteAuthors can edit or delete their messages; edit history tracked; deleted messages show placeholder
  • ✓Read ReceiptsPer-message read status showing which team members have seen each message
  • ✓Message SearchFull-text search within the team chat history; results highlight matching terms
  • ✓Real-Time DeliveryMessages delivered instantly via dedicated team-chat Socket.IO gateway with typing indicators
